# cy_quant/monitor：120 日均线池监控与回测 — 实现说明

**版本**：v0.1（待确认后开发）  
**日期**：2026-04-20  
**状态**：草案，以本文为准进入实现；未确认前不改代码。

---

## 1. 目标与范围

### 1.1 目标

- 以 **「站上 120 日均线」股票池**（CSV）为唯一监控范围。
- **每日 K 线更新仅针对该池内股票**，不全市场更新。
- 在 **纯 CSV + `cy_quant/monitor`** 内完成：状态、信号、回测成交与汇总；**不依赖 cy_ai、不依赖 MySQL**。
- 规则与此前约定一致：**入场 T+1 开盘价**；**出场** 采用可配置止损（含 **跌破 120 日均线**、参考 `MonitorStockAPool.py` 的 **ATR 类止损/止盈** 思路）。

### 1.2 非目标（本阶段不做）

- 不在本文档范围内实现订单撮合、实盘下单接口。
- 不强制与 abupy 回测数值逐笔一致；若后续要对齐，可再开「适配层」专项。
- cy_ai 监控服务、飞书通知可作为后续扩展，**不作为本阶段交付物**。

## 2. 输入与输出

### 2.1 输入

| 名称 | 说明 |
|------|------|
| 股票池 CSV | 如 `cy_quant/sh_120ma.csv`，至少包含 `ts_code` 列；`dtype` 读取时 **必须将 `ts_code` 作为字符串**，保留前导零（如港股 `09866`）。 |
| 本地 K 线存储 | 与现有工程一致：如 `~/abu/data/csv/` 下按 `sh600036_日期_日期` 等规则命名的文件；具体路径 **可配置**。 |
| 配置 | 建议使用 `cy_quant/monitor/config.yaml`（或 `config.json`）：池文件路径、数据根目录、止损模式、ATR 参数、输出目录等。 |

### 2.2 输出（建议路径：`cy_quant/monitor/` 或 `cy_quant/monitor/output/`）

| 文件 | 用途 |
|------|------|
| `positions_state.csv` | 状态机：代码、锚定日/锚定价、是否已入场、入场价、止损参考、状态等。 |
| `signals_YYYYMMDD.csv` | 当日扫描结果：买入提示、止损触发、创新高观察等（可追加或按日新文件）。 |
| `backtest/trades.csv` | 回测：每笔交易开平仓记录。 |
| `backtest/summary.txt`（或 `.md`） | 回测汇总：笔数、胜率、平均盈亏、最大回撤等。 |
| `logs/`（可选） | 运行日志。 |

## 3. 股票代码与符号映射

- 池内 `ts_code` 可能为：`600036`、`688003`、`000001`、`09866`（港股）等。
- **内部统一**为数据文件所用前缀格式（如 `sh600036`、`sz000001`、`hk09866`），与 `Monitor120MAStrategy` / 现有 `cy_quant` 脚本保持一致。
- **映射规则**须单独函数 + 单元测试样例，避免 silently 错配文件。

## 4. 每日 K 线更新（仅 120 日均线池）

### 4.1 需求（已确认）

- **每日 K 线更新仅针对当前 120 日均线池中的股票**，不执行全市场 `run_kl_update`。

### 4.2 实现原则

- 从池 CSV 读取代码列表 → 映射为 abu / 本地文件名所用 symbol → **仅对这些 symbol 拉取或增量更新 K 线**。
- 若 **abupy** 提供「按 symbol 列表更新」的 API，则直接调用；若仅支持全市场，则实现为：
  - **循环**：对池中每个 symbol 调用可用的单票更新接口；或  
  - **调用底层数据源**（与 `ALLAMarketPickStock` 一致的数据源，如腾讯 + CSV 缓存）仅请求池内代码。  
- 具体调用方式在开发阶段查阅 `abupy` 与 `abu.run_kl_update` 文档后确定，**以「只更新池内」为验收标准**。

### 4.3 失败与重试

- 单股更新失败：记录日志，写入 `update_failures_YYYYMMDD.txt`，不中断整批（可配置）。
- 频率：默认每个交易日盘后执行一次（与任务调度约定一致即可）。

## 5. 策略规则（与方案一致）

### 5.1 入场

- 信号在 **T 日收盘** 可确认（例如：站上 120 日均线、或「突破」定义与池子生成逻辑一致）。
- **成交价**：**T+1 日开盘价**（回测与模拟监控一致）。

### 5.2 出场（可配置，多选一或组合「先触发先走」）

| 模式 | 说明 |
|------|------|
| **跌破 120 日均线** | 收盘价低于当日 MA120（MA 用截至当日的历史数据计算）。触发后卖出价规则见 5.3。 |
| **ATR 止损** | 参考 `MonitorStockAPool.py` 中 `AbuFactorAtrNStop` 思路：如亏损达到 `stop_loss_n × ATR(14)`；参数写入配置。 |
| **ATR 止盈/其他** | 可选：`stop_win_n × ATR` 或与 `AbuFactorPreAtrNStop` / `CloseAtrNStop` 思路一致的简化版，**仅实现与文档一致的简化规则**，避免与 abu 内部细节强行逐行一致。 |

### 5.3 卖出成交价（回测与文档化）

- 需在配置中 **固定一种**（避免歧义）：
  - **均线破位**：例如「信号日 T 日收盘确认跌破 → **T+1 开盘价** 卖出」或「T 日收盘卖出」二选一。
  - **ATR 止损**：例如「当日 **low** 触及止损价 → 按止损价成交」或「收盘确认触及 → 收盘价成交」二选一。

默认建议：**破位用 T+1 开盘卖**（与入场 T+1 对称）；**ATR 用盘中 low 触及止损价**。

### 5.4 锚定与创新高（可选）

- **锚定价**：突破日（或站上 120 日均线确认日）收盘价。
- **创新高**：收盘创锚定以来新高——可作为 `signals` 中的 **观察标签**，不替代止损逻辑。

## 6. 日频监控流程（CSV 状态机）

1. 读取池 CSV → `choice_symbols`。
2. 执行 **§4 仅池内 K 线更新**。
3. 加载每只股票 K 线，计算 MA120、ATR（若启用）等。
4. 更新 `positions_state.csv`：未入场 → 待入场；已入场 → 检查止损/止盈。
5. 追加 `signals_YYYYMMDD.csv`。
6. （可选）若后续增加「盘中现价」，仅对 **池内或持仓子集** 请求快照，**不写库，只写 CSV**；本阶段可不做。

---

## 7. 回测流程

- 使用 **与监控相同** 的入场/出场函数，避免回测与实盘规则漂移。
- 输入：历史 K 线 + 池列表（或历史上按日重构的池子）。
- 输出：`backtest/trades.csv`、`backtest/summary.txt`。
- **无未来函数**：信号仅使用 T 日及之前数据；成交价为 T+1 open。

## 8. 配置项（建议）

- `pool_csv`：池文件路径。
- `data_root`：本地 K 线根目录。
- `output_dir`：`monitor` 输出目录。
- `entry_rule`：站上 MA120 的定义（与现有 `Analyze120MA` / 池生成脚本对齐，或引用同一参数）。
- `exit_mode`：`ma120_below` | `atr` | `combined`。
- `atr_period`，`stop_loss_n`，`stop_win_n`（可选）。
- `sell_fill`：`next_open` | `close` 等（与 §5.3 一致）。

## 9. 依赖与工程约束

- **Python**：与项目主版本一致（如 3.9+）。
- **pandas / numpy**：必须。
- **abupy**：若 K 线更新与读取沿用 `ALLAMarketPickStock` / `AbuKLManager`，则依赖现有 `abu_local_env`；若改为 **仅 pandas 读 CSV**，则可降低对 abu 的耦合，**开发阶段二选一并在本文档修订「数据读取层」**。

---

## 10. 验收标准（建议）

1. 给定小型测试池（3～5 只股票），跑一日流水线：**仅更新池内** K 线、无全市场更新；日志与 `positions_state.csv` 可追溯。
2. 回测脚本：对同一规则，**手动抽查 1～2 笔**开平仓价格与 T+1 open、止损逻辑一致。
3. 配置修改后，**不改动核心逻辑**即可切换「仅 MA120 破位」与「MA120 + ATR」。
